## 一、问答概要

### 1. 自我介绍
**问**:请自我介绍一下。
**答**:2024 年 7 月入职招银网络科技(招商银行信息技术部独立出来的公司),团队负责银行底层交易系统(汇款转账、记账),所在小团队做跨境上游端——对接外部金融基础设施、收发并解析报文、调整报文顺序、清分给下游业务系统、银行间记账。主要项目:SWIFT 对接、跨境数字人民币。技术栈 Java + Spring Boot。

### 2. Spring Cloud / 微服务
**问**:了解 Spring Cloud 吗?怎么理解微服务?常用微服务有哪些组件?
**答**:团队用 Spring Cloud 搭过基础设施;微服务 = 很多应用各司其职,靠「注册中心 + 服务保障中心」上报、监控可用性、调度分发,把单体转成多小应用协同。组件只说出了「注册发现中心(Nacos,名字不笃定)、网关、消息队列」,较犹豫、不完整。

### 3. Spring Boot
**问**:对 Spring Boot 的了解?
**答**:Java 开发框架,把类注册成「Bean」放进「容器」,Spring 管理容器;配置快、免从零搭建、能集成数据库/消息队列等组件,是「快捷开发的脚手架」。—— 表述混乱,把 Bean 与容器概念搅在一起。

### 4. 多线程
**问**:什么情况用多线程?有哪些方式?解决什么问题?可能出什么问题?
**答**:目的是提速,单线程慢就多线程并行。问题:线程抢资源,要加锁避免资源误用;并发导致资源消耗不符预期,需并发控制。工作中:一条交易一个线程;起异步线程处理主流程外的任务;多分库查询时每库一线程(比串行快),需等待、结果集中处理。—— 较泛,未触及线程池/锁机制/可见性等核心概念。

### 5. DDD
**问**:对 DDD 的理解?它和常规模式有什么区别?
**答**:从系统设计与代码实现两角度:设计上描绘业务领域、提炼领域对象(用户/事件等);实现上分四层(接口层、应用层、领域层、基础设施层)。区别:DDD 倾向给领域对象加方法(举「老虎捕食」例子,即充血模型),传统方式对象只存数据、行为放其他层(即贫血模型)。—— 方向对、结构较系统,但未点出「贫血/充血模型」术语及聚合根等概念。

### 6. AI Agent / Skill
**问**:AI Agent 的使用情况?提炼过什么 Skill?
**答**:公司内网自研编程 Agent,委派确定/重复的逻辑;把「重复性高、需上下文理解」的活提炼成 Skill,团队共享。做过:应用国产化中 Oracle→国产数据库(如 TDSQL)的 SQL 改造 Skill,内置 reference 参考文件 + 提示词。—— 答得具体,是本场最好的一题。

### 7. 反问
**候选人反问**:团队做什么业务?
**面试官答**:银行资金管理系统(工具型),面向银行——银行有自己的客户,通过该系统管理不同客户间的资金往来与资金计划;定制化交付。—— 候选人反问较被动、绕。

## 二、面试缺点

1. **表达力弱(最突出)**。全程大量「呃 / 嗯 / 就是 / 怎么说呢 / 然后」口头禅,句子支离破碎、逻辑跳跃,几乎每题都是碎片化输出,缺少「先结论、后分点」的结构。
2. **技术概念不扎实、术语缺失**:
   - **Spring Boot**:把 Bean 说成「容器」、说「Spring 管理各个容器」,IoC 容器与 Bean 对象概念混淆,停留在「脚手架」表面。
   - **Spring Cloud**:组件只会泛泛说「注册发现中心、网关、消息队列」,说不出配置中心、OpenFeign、Sentinel、负载均衡等具体组件,且对 Nacos 名字不笃定(「ncks 是吧?应该是一个吧」)。
   - **多线程**:停留在「提速 + 加锁」层面,未涉及线程池、锁的种类、volatile / CAS、JMM 三大特性(可见性/有序性/原子性)。
   - **DDD**:没说出「贫血模型 / 充血模型」这两个关键术语,也未提聚合根、限界上下文等核心概念(只提到「领域事件」一词)。
3. **回答无结构**:想到哪说到哪,本可 1/2/3 分点讲清楚的(多线程、Spring Boot)全都讲乱了。
4. **反问环节弱**:问题绕(「据我所了解……是不是……」)、显得不自信,缺少准备。

---

## 三、可改进点

1. **表达训练**:刻意用「结论先行 + 1/2/3 展开」的结构;录自己的回答复盘,量化地减少口头禅。
2. **术语精准**:背熟核心组件的准确名称(Nacos、OpenFeign、Sentinel、Gateway、Ribbon/LoadBalancer、Seata 等),避免张冠李戴、不敢说全名。
3. **概念体系化**:每个高频考点按「是什么 → 原理 → 怎么用 → 场景/坑」四层准备,保证每题能讲满 2 分钟。
4. **准备反问**:准备 2–3 个高质量问题(业务方向 / 技术栈演进 / 团队成长空间 / 「对我本次表现有何建议」),展现主动性。
5. **简历深挖 mock**:简历亮点(分布式事务、多分库、DDD、Kafka、千万级迁移)必被追问,逐条准备 3 层追问的回答。

## 四、缺少的知识点

1. **Java 并发**:JMM(可见性/有序性/原子性)、synchronized / ReentrantLock / AQS、volatile、CAS、ThreadLocal、线程池参数与原理、死锁、CountDownLatch / Semaphore。
2. **Spring 核心**:IoC / DI 原理、Bean 生命周期、自动装配原理、starter 机制、AOP。
3. **Spring Cloud 全家桶**:配置中心(Nacos Config / Apollo)、服务调用(OpenFeign)、熔断限流(Sentinel / Hystrix)、负载均衡、网关(Gateway)、链路追踪。
4. **DDD 术语与建模**:贫血 / 充血模型、实体 / 值对象、聚合与聚合根、限界上下文、领域事件、防腐层。
5. **分布式事务**:2PC / 3PC / TCC / SAGA / 本地消息表 / 最终一致性(简历写了,需能深讲)。
6. **消息队列**:Kafka 的消息可靠性、顺序性、重复消费、堆积处理(简历用到 Kafka)。
7. **数据库**:索引(B+ 树)、事务隔离级别、锁、MVCC(Oracle / TDSQL)。

---

## 五、下一步建议学习的知识点(按优先级)

1. **Java 并发编程**(最高优先):本场被问且答得最浅,系统学习 JMM、锁、线程池、AQS,并准备「工作中怎么用」的实例。
2. **Spring 核心 + Spring Boot 自动装配**:先纠正 Bean / IoC 容器等基础概念,再讲透自动装配、starter、生命周期。
3. **Spring Cloud 微服务组件**:结合工作补全 Nacos / OpenFeign / Sentinel / Gateway,能说出各自作用与原理。
4. **DDD 系统化**:补术语(聚合根、限界上下文、贫血/充血模型),结合数字人民币项目讲落地。
5. **分布式事务 + 消息队列**:把简历里的「本地消息表 + Kafka 补发 + 最终一致性」讲透,这是你区别于同龄人的亮点。
6. **数据库索引 / 事务 / 锁**:简历写了 Oracle / TDSQL,必须能深讲索引与事务隔离级别。
