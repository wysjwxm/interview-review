## 2. 面试缺点

**主因:算法题没做出来,直接决定一面结果。**

1. **算法题失败,现场调试效率低**
   - 回溯初始参数传 K=0,逻辑自相矛盾,被面试官一眼点出(「你这个 K 一开始传 0,你觉得对不对?如果 K 传成 1 的话,它还要拆吗?」)。
   - 面试官明确指出"边界条件上面有两个地方是有问题的",说明不只是调试问题,是边界/终止条件的系统性疏漏。
   - 全程靠打日志试错,未静态跑小样例定位,耗时过长(主动要"再给两三分钟"),最终被切断。

2. **数据库基础不扎实,不确定时靠"猜"**
   - MySQL 默认隔离级别先说成读已提交(受 Oracle 习惯影响),说明日常只偏使用、没建立概念对比。
   - RR/RC 区别讲不清;MVCC 快照机制理解错误,被面试官当面纠正并点破"我觉得你是猜测是吧?——对的"。面试里猜答案比说不知道更伤。

3. **分布式概念混淆**
   - 说不清 TDSQL「分布式」到底指什么,把"存储节点分布式"与"高可用(多副本备份)""分库分表(数据分片)"混为一谈,连续追问后放弃。

4. **分布式锁/事务只有概念、没有实践深度**
   - 生产没用过分布式锁,场景与方案都需要面试官引导才给出(`for update`、CAS),缺乏自主组织的体系。

5. **项目难点答得空泛**
   - 迁移方案讲的是"无中断、灰度、回滚、动态数据"几个词,没有落到具体做法(如何灰度、回滚粒度、数据校验方式),缺说服力。

## 3. 可改进点

**针对算法(本次直接决定挂因,优先级最高):**

1. **专项练回溯/DFS 的边界条件**:每个模板(拆数、组合、排列、子集)练到"不调试一次 AC"。本题正确做法是 DFS 枚举每段长度,初始传目标段数 K,当剩余段数==1 时直接把剩余数字取整段作为最后一段;注意 `L-1` 个间隔选 `K-1` 个切口、段非空、字符串长度边界。
2. **现场 debug 策略**:写完后先拿题目小样例(N=1234,K=3)手跑一遍状态转移,而不是直接打日志试错;给自己设调试时间上限(3 分钟),超时主动换思路或向面试官求助(求助不失分,耗死在调试才失分)。
3. **模拟限时环境**:用周赛/限时题训练时间压力下的编码与取舍能力。
4. **规范命名与自测**:避免 `MaxK` 这类含义不明的命名;写完先自查初始参数与终止条件两个"最容易挂"的位置。

**针对数据库八股:**

5. **把 MySQL 默认隔离级别记牢并对比**:MySQL 默认 RR、Oracle 默认 RC,一句话讲清差异,别再被习惯带偏。
6. **理解 MVCC 而非背概念**:read view 生成时机(RC 每条语句新快照、RR 整个事务复用同一快照)、快照读 vs 当前读;这正好能回答"为什么 RR 保证可重复读、RC 并发度/性能更高"。
7. **不确定就坦诚**:面试官明说"不清楚可以直接说",答"这块我没深究,方向上是 XX"比瞎猜好得多。

**针对分布式与项目:**

8. **建概念地图**:高可用(主从/副本/备份)≠分布式/分片(数据切分)≠分布式事务/锁,三件事分开讲清。
9. **把简历技术点准备成"三层深水区"**:简历写了"事务、锁、索引""分布式事务处理",面试官必深挖——每个点备到"是什么→为什么→底层原理"。
10. **AI 项目补强**:准备模型选型对比(为什么选 DeepSeek/讯飞而非豆包——成本/效果/生态),准备量化指标(转录准确率、建议采纳率)与迭代规划(晋级概率预测、多模型 A/B),把亮点讲成有含金量的产出。

## 4. 缺少的知识点

面试中明显暴露、未掌握或答错的知识点:

1. **回溯/DFS 边界条件**:初始参数设计(剩余段数的正确初值)、终止条件、剪枝(本题:拆数字最大化乘积)。
2. **MVCC 机制**:read view 的生成与复用、快照读/当前读、undo log;RC 与 RR 在快照上的差异及对性能的影响。
3. **隔离级别**:MySQL 默认 RR、Oracle 默认 RC;脏读/不可重复读/幻读分别由哪级解决;间隙锁/next-key lock。
4. **分布式数据库架构**:TDSQL 的计算/存储节点、数据分片原理,以及"分布式"与"分库分表""高可用"三者区别。
5. **分布式锁与分布式事务**:Redis SETNX/Redisson、DB `for update`、CAS 乐观锁;2PC/TCC/本地消息表/最终一致性。
6. **联合索引细节**:最左前缀、范围查询后字段的索引利用、`order by` 走索引与 filesort、覆盖索引。
7. **TDSQL 具体特性**:项目在用却没深入了解(兼容性、分布式事务、强一致策略)。

## 5. 下一步建议学习的知识点(优先排序)

结合目标岗位(字节·抖音钱包,支付领域,Java)与简历短板:

1. **算法(最高优先)**:回溯/DFS 模板与边界条件、动态规划(本题拆数最大化乘积本质可用 DP 解)、限时刷题训练。算法挂了本次面试,是投入产出比最高的地方。
2. **MySQL InnoDB 原理**:隔离级别、MVCC、锁(行锁/间隙锁/next-key)、索引最左前缀与覆盖索引、EXPLAIN。本次暴露最严重,且支付场景必考。
3. **分布式基础**:分布式锁(Redis/DB/ZK)、分布式事务(2PC/TCC/本地消息表/Seata)、幂等与去重。简历写过分布式事务,必须能讲深讲透。
4. **TDSQL / 国产数据库**:架构、与 MySQL 的差异、分库分表实践——简历项目在用,面试官一定会追。
5. **支付领域业务**:幂等、对账、防重、冲正/调账、定时任务驱动状态机——结合自己项目把故事讲完整、量化(灰度比例、回滚时间、数据校验方式)。
