## 一、问答实录

### Q1. 地点与长沙意向
- **面试官问**：开场确认——福建人愿意去长沙吗?对工作地点长沙有了解吗?
- **候选人答**：愿意;没去过长沙,了解不多。
- **评分与点评**：80/100 · 坦率,意愿表达明确;面试官对此评价「挺敢闯」,是加分的第一印象。

### Q2. AI 的应用(工作 + 生活)
- **面试官问**：讲一下 AI 吧,AI 有什么学习应用?
- **候选人答**：从工作与生活两方面谈。工作:行内团队自研编程 agent,有内部 skill 市场、MCP 市场;把死板流程(改 SQL 语法、写单测)沉淀成 skill 文档交给 AI;近期在做数据库国产化改造。生活:用 Claude Code 搭了面试复盘项目,上传简历+录音让 AI 流程生成复盘文档。
- **评分与点评**：90/100 · 结构化(两分法)、有具体案例、与简历「Agent/MCP/Skills 有实践」完全一致,是全场最强答案。

### Q3. DDD(领域驱动设计)
- **面试官问**：讲一下 DDD 吧。(追问)你具体用这个设计完成了哪些工作?
- **候选人答**：数字人民币支付平台从零设计时参考 DDD。业务层面:从用户故事地图画起、识别领域对象,抽离报文/清算/账户模块实现解耦;技术层面:三层架构转四层架构。具体工作:按「路由层(转发+原文存储)→ 报文层(解析)→ 记账层(过渡账)→ 清分业务系统 → 次日区块链对账」讲解系统,自己负责报文解析与报文路由。
- **评分与点评**：75/100 · 系统讲解完整、可信;但 DDD 本身答得浅——只到「业务/技术分层 + 解耦」,没提**限界上下文、聚合根、领域事件、事件风暴、防腐层**等核心概念,「用户故事地图」点到未展开。

### Q4. 项目深挖·数字人民币报文系统
- **面试官问**：DDD 这个设计思想你具体完成了哪些工作?
- **候选人答**：模块划分;专线接入→HTTPS 卸载→解密解签→路由层转发并异步(MQ)消费持久化原文→分库分发→报文层解析提取交易信息落库→记账层记过渡账→按要素匹配清分业务系统;次日统一拉取做区块链对账。
- **评分与点评**：85/100 · 链路清晰、有具体实现细节(专线/软载/解签/MQ 持久化/分库分发),真实工程感强;但信息量大、靠面试官提示才讲完整,主动性略弱。

### Q5. DDD 与 AI 编程的联系
- **面试官问**：DDD 跟 AI 编程有些什么联系吗?
- **候选人答**：两件事,解决不同痛点——DDD 做业务划分与解耦,AI 编程做开发提效;但可以把 DDD 设计思想用规范形式约束 AI,让 AI 推进系统建设。
- **评分与点评**：78/100 · 有思考、有亮点(用 DDD 规范约束 AI);但答得短,未展开「如何把领域模型/规范喂给 AI、边界如何落地」,追问空间没接住。

### Q6. 职业规划
- **面试官问**：自己有些什么职业规划?想往什么行业发展?对金融感兴趣吗?
- **候选人答**：入职两年一直做支付业务,希望在这个领域继续深入、加强经验能力;对金融感兴趣、有炒股买基金,没有境外账户。
- **评分与点评**：70/100 · 方向真实但单薄——只讲「想深耕支付」,被追问行业才补「金融」,没主动把支付/SWIFT 背景连接到目标岗位(股票交易/清结算),叙事缺「为什么是这家公司」。

### Q7. 金融兴趣与境外账户
- **面试官问**：对金融感兴趣吗?有没有炒股、买基金?有境外的账户吗?
- **候选人答**：感兴趣;有炒股、买基金;没有开境外账户。
- **评分与点评**：80/100 · 如实、干脆,合规问题无坑。

### Q8. 反问·岗位与业务
- **候选人问**：现在做的主要是股票交易吗?B 端股票交易指什么(基金公司)?系统是搭建早期还是维护期?用户量多大?交付是私有部署还是 SaaS?
- **面试官答**：岗位做股票交易,可轮岗或转 AI;香港券商做股票业务成本高(系统+行情一套约 3000 万/年),需要供应商;系统处于早期重构,拿兄弟公司「新财富」成熟代码做下一代(加公募私募、票据 + AI);兄弟公司日活十几万,这边刚开始;交付主流是 SaaS。
- **评分与点评**：—(反问一般不评分)· 问题具体、能获取关键信息,是正向互动;唯一可以更早抛出「岗位核心要求/考核方式」。

### Q9. 待遇期望
- **面试官问**：待遇方面怎么考虑?现在总包多少?
- **候选人答**：去长沙希望有 10–20% 涨幅;现年包 28 万;得知公司长沙普遍打 7 折后表示理解但未再争取。
- **评分与点评**：75/100 · 沟通客观、不纠缠;但期望与市场现实落差大(想涨 10–20% vs 普遍 7 折),说明**没提前调研目标城市/公司的薪酬水平**,HR 阶段最容易被卡。

### Q10. 反问·团队规模
- **候选人问**：团队多大?多少开发多少测试?长沙多少人?
- **面试官答**：团队 150 人,产研整个公司 200 多人;主要往长沙扩编,长沙现约 30 人。
- **评分与点评**：—(反问一般不评分)· 提问自然。

## 二、面试缺点

1. **表达碎、口头禅多、句子不完整(最突出)**:全场高频「嗯」「呃」「那个」「诶」「就……就……」「这种的」,句子经常说一半换方向。尤其 Q3 DDD 与 Q4 项目深挖,信息量很大但结构散,靠面试官多次追问/提示才拼成形;本可 85+ 的答案被表达拖到 70+。
2. **概念题「会说不会讲透」(Q3 DDD)**:DDD 只答出「分层 + 解耦」,核心术语(限界上下文、聚合根、领域事件、事件风暴、防腐层)一个没提,「用户故事地图」点到为止——说明对 DDD 停留在「用过的经验」层面,没上升到「为什么、怎么做」。
3. **职业与薪资叙事弱(Q6/Q9)**:职业规划只说「想深耕支付」,没主动连接目标岗位;薪资期望(涨 10–20%)与长沙市场(普遍 7 折)脱节,暴露求职前对城市/公司薪酬调研不足。
4. **匹配度表达被动**:SWIFT/跨境支付/报文/清结算背景与股票交易、财富管理、清结算有明显可迁移性,但候选人全程没主动把这段背景「翻译」成目标岗位的价值,靠面试官自己发现(反问 SWIFT)。
5. **反问偏事实性、偏晚**:问题集中在系统阶段/用户量/交付模式/团队规模,利于了解但不利于展示匹配意愿;可在中段抛出「岗位核心要求、考核方式、技术栈」类问题。

## 三、下一步学习计划

> 排序依据:本场暴露严重度(答错 > 靠猜 > 遗漏)为首要,并参考 `知识点统计.csv` 累计频次与 `weight` 注释。

1. **DDD 核心概念补全(本场最薄的技术题)** — Q3 只答到「分层 + 解耦」。
   - 动作:系统学限界上下文、聚合根、领域事件、事件风暴、防腐层、CQRS;背熟 DDD 标准答题框架「是什么 / 为什么 / 怎么落地 / 优缺点」;结合自己项目(数字人民币报文系统)画一遍「模块 → 限界上下文 → 聚合」映射,讲出「三层转四层」的架构动机。

2. **即兴表达结构化(重点练)** — 全场结巴、结构散,是最大主观失分。
   - 动作:把「AI 应用、DDD、数字人民币报文系统」写成**分点腹稿**;用「第一…第二…第三…」作答,答案做成「结论先行 + 要点支撑」;对镜/录音自讲 2 分钟版本,刻意去掉「嗯/呃/那个」;项目链路(Q4)练成一段顺口流利的 90 秒介绍。

3. **职业叙事与金融行业连接** — Q6 单薄、匹配度表达被动。
   - 动作:准备 30 秒「为什么深耕支付/金融」;把 SWIFT/跨境支付/报文/清结算经验显式映射到「股票交易、清结算、财富管理」场景,主动讲「我在跨境支付的哪些能力能迁移到你们岗位」。

4. **薪酬调研与谈判策略** — Q9 期望与市场脱节。
   - 动作:面试前查目标城市(长沙)IT 薪酬区间与目标公司/同行口径;设定「期望值 + 底线」;被压价时用「涨幅 vs 购买力 vs 成长性」重新对齐,而不是当场坚持或立刻让步。

5. **保持并方法论化 AI/Agent 工程应用(强项)** — 本场最高分题。
   - 动作:把「skill/MCP 市场、Claude Code 面试复盘项目、AI 生成复盘文档」整理成可复述的方法论与 1–2 个含量化案例,作为后续面试的稳定亮点。

6. **补股票交易/清结算领域知识(新岗位方向)** — 目标是 B 端股票交易/财富管理岗位。
   - 动作:了解香港券商牌照体系(1 号牌证券交易等)、股票交易系统组成(交易/清算/结算/行情)、B 端券商供应商形态(SaaS vs 私有部署);对比跨境支付与证券清算的异同,为下一轮技术面储备。
